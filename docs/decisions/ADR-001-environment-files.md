# ADR-001：环境配置文件格式与 `${env:...}` 的含义

- 状态：已采纳
- 任务：P0-31
- 日期：2026-11-08

## 背景

`develop.md` 说明了环境级的 base_url、变量，以及凭据以 `${env:VAR}` 引用保存，但没有规定环境文件的结构，也没有说明 DAG 模板里的 `${env:NAME}` 读的是操作系统进程环境变量，还是所选环境配置里的变量。这个选择会影响用户编写的 YAML，也会影响 CLI 的 `--env` 参数，因此需要明确下来。

## 选项

1. DAG 中的 `${env:NAME}` 直接读进程环境变量，环境文件只提供 base_url。
2. DAG 中的 `${env:NAME}` 读所选环境的变量；环境文件中的值可以用 `${env:VAR}` 引用进程环境变量。
3. 先查环境变量，查不到再回退到进程环境变量。

## 决定

采用选项 2。

```yaml
# environments/<name>.yaml
base_url: http://localhost:8080       # 必填，在模板中以 ${env:BASE_URL} 暴露
variables:                            # 可选，值只能是字符串
  TENANT: acme
  API_KEY: ${env:AITEST_API_KEY}      # 加载时从进程环境读取
```

- 文件名即环境名，只允许 `[A-Za-z0-9_-]`，防止路径穿越。
- 环境文件中只允许出现 `${env:...}` 引用，`$${` 转义可用；节点引用和 `${auth...}` 都直接报错。
- 加载时一次性报告全部缺失的进程变量，同时给出引用它的字段。运行前用 `Environment::check_dag` 一次性列出 DAG 中引用但环境未定义的变量，并给出节点和 JSON Pointer。
- `variables` 中不得出现 `BASE_URL`，避免与 `base_url` 冲突。
- 来自进程环境的值标记为可能是机密：`Debug` 输出显示为 `****`，`is_from_process` 供后续快照脱敏使用。
- 进程环境通过 `ProcessEnv` trait 注入，测试使用 `BTreeMap`，不修改真实进程环境。

## 后果

- 同一个 DAG 只要切换环境文件就能指向不同系统，DAG 本身不直接接触进程环境，确定性只取决于"DAG + 环境配置"。
- 选项 3 的隐式回退会让运行结果受到无关进程变量的影响，因此不采用。
- `keychain://` 与 `${auth.*}` 的解析不在这里处理：分别属于 P2-01（secrets crate）和 P3-11（认证方案），届时会在环境文件中新增 `auth` 段。在此之前，`auth` 字段会被当作未知字段拒绝。
