# ADR-005：直接运行 DAG 文件时的版本记录

- 状态：已采纳
- 任务：P0-48
- 日期：2026-11-08

## 背景

`mytool run --dag <id|file>` 既可以运行库中某个 DAG 的 active 版本，也可以直接运行一个文件（`AGENTS.md` 的示例命令和 P0-53 的 golden 测试都直接运行 `examples/*.yaml`）。但 `dag_runs` 对 `(dag_id, dag_version)` 有指向 `dag_definitions` 的外键，P0-50 的 `run show` 也要从库里回放证据。所以文件运行的证据必须挂在某个已存的 DAG 版本上。

## 选项

1. 文件运行不落库，只打印结果。这样就没有 `run show` 和失败记录，验收用例（超时回放）做不了。
2. 去掉外键，`dag_runs` 另存 DAG 内容快照。这需要迁移，并且和 §3 的数据模型不一致。
3. 运行前把文件内容存成版本：先过保存闸门（`Gate::for_save`），如果该 id 已有内容完全相同（规范化 JSON 相等）的版本就复用它，否则保存为新的 `pending` 版本，运行引用这个版本。

## 决定

采用选项 3。

- `--dag` 的值是已存在的文件路径，或以 `.yaml`/`.yml`/`.json` 结尾时按文件处理；否则按 DAG id 处理，运行它的 active 版本，没有 active 版本时报错。
- 文件运行不改变任何版本的状态：新版本是 `pending`，激活仍然只能通过 `dag activate`（红线 4）。子工作流引用仍然只解析到激活过的版本。
- 同一内容重复运行复用同一个版本，不会每次运行都新增版本。

## 后果

- 文件运行会在库中留下 `pending` 版本，`dag list` 中可见。这正好记录了"这次运行跑的是什么内容"。
- 运行 `pending` 版本只是一次性执行，不代表该版本被认可；P1 的 server 运行 API 也沿用这条规则。
